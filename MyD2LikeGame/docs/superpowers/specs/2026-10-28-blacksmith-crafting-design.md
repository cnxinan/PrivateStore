# 铁匠学习与装备打造设计

## 目标与范围

把当前“打怪直接获得装备”改为：
打怪获得材料和配方 → 拾取 → 交给铁匠学习 → 消耗材料打造装备 → 比较并穿戴。
本轮以可完整试玩的最小闭环交付，不引入装备经验/等级、金币、打造失败、
打造等待时间、出售、分解、批量打造、存档或通用物品框架。

退出游戏清空进度；“永久学会”仅指当前运行期间。
死亡和R重开保留全部已拥有装备、资源数量和铁匠已学配方。
保持既有战斗数值、怪物行为、程序动画、两槽属性及词缀规则。
先前“每怪必掉一件装备”是本次明确替换的旧行为，不再作为生产规则。

工作区复用feature/darkloot-vertical-slice的已有隔离目录。
设计批准后才制定实现计划；实现前另行确认执行方式。

## 已选方案与边界

采用独立资源袋＋铁匠学习状态＋打造服务。
不把材料/配方伪装成ItemInstance，也不重建通用物品系统。

- Data：材料、配方、费用、资源掉落表的JSON定义与引用校验。
- Gameplay资源袋：按材料ID/配方ID分别持有数量，提供只读查询和受限提交。
- Gameplay铁匠状态：持有当前运行已学会的配方ID集合。
- Gameplay学习/打造服务：检查门禁、预计算候选状态并原子提交。
- Gameplay装备生成：从现有LootGenerator提取固定模板/品质的词缀生成能力。
- Gameplay击杀奖励：保留轮次/怪物实例去重，奖励内容换成资源。
- Game：铁匠形状、中文面板、输入路由和提示；不直接写集合或材料数量。

Gameplay继续独立于MonoGame、Engine和Game。沿用普通方法调用，不增加事件总线、
插件奖励系统、ECS、全局仓库或通用事务框架。
已有纯属性计算器、装备唯一快照归属和统一装备操作入口继续使用，
不能为了打造增加绕过校验的装备入包路径。

## 第一版内容

### 材料与掉落

| 怪物类型 | 必掉材料 | 数量 |
|---|---|---|
| 史莱姆 | 黏液 | 1～2，等概率 |
| 狼 | 兽皮 | 1～2，等概率 |
| 骷髅弓手 | 骨片 | 1～2，等概率 |

每只怪物在材料之外，独立有20%概率掉1张配方。
四张配方等概率，各占所有击杀的5%；允许重复，也允许掉已学配方。
每次击杀产生一堆材料，最多再产生一堆配方，不直接产生装备。
掉率、数量、材料对应关系和配方候选列表数据驱动，不写死在近战或UI。
不按已学配方动态调整概率，不提供保底学习或初始赠送配方。
玩家初始仍空手，已有基础攻击可完成战斗，不必先打造才能打怪。

资源掉落表与旧装备掉落表语义明确区分；生产怪物改为引用资源掉落表。
旧装备生成算法如仍被测试使用，可保留为窄用途代码，但不能成为生产怪物掉装备的旁路。
不留下未使用的旧生产掉落配置，文档和生产内容测试同时迁移。

### 配方

复用现有训练武器/护甲模板，只改变固定品质和随机词缀。

| 配方 | 产物 | 材料费用 |
|---|---|---|
| 魔法武器配方 | 魔法训练武器，1条词缀 | 骨片×2、黏液×1 |
| 魔法护甲配方 | 魔法训练护甲，1条词缀 | 兽皮×2、黏液×1 |
| 稀有武器配方 | 稀有训练武器，2条词缀 | 骨片×4、兽皮×2、黏液×2 |
| 稀有护甲配方 | 稀有训练护甲，2条词缀 | 兽皮×4、骨片×2、黏液×2 |

配方固定模板与品质，不随机品质；每次打造重新选择适用词缀及数值。
同一件稀有装备的两条词缀不重复，使用现有词缀池、数值范围、命名和属性计算。
打造100%成功、立即完成，无金币费用。每次成功创建新的非空InstanceId，
不复用或改写旧装备，不自动穿戴，不治疗。
装备数量不设新的容量限制；资源数量使用非负整数并检查溢出，不环绕或静默截断。

## 资源归属与地面拾取

资源袋按ID堆叠材料、配方，二者不占装备实例列表。
配方物品和铁匠知识分开：袋里有配方不代表铁匠已经会打造。
背包提供“装备/资源”切换，资源页显示拥有的材料和配方名称、数量；
装备页保留既有比较与穿戴行为。

地面显示资源名称和数量。保留现有防重叠布局和指向真实位置的连线。
按E拾取范围内最近一堆，沿用原有范围/距离选择规则；材料和配方不自动吸入。
成功入袋后才能移除地面对象，失败保留地面对象且不部分加数量。
地面堆有稳定身份，防止同一掉落重复转移；资源入袋后按定义ID累计数量。
同一击杀的两堆可以处于相同世界位置，由已有显示布局分开，不改变拾取距离。

R和复活仍清掉全部未拾取战利品，保留已经入袋的资源。
资源定义、数量、引用非法时明确报错，不用零数量/未知名称兜底。

## 铁匠与面板

铁匠是固定场景对象，放在出生点附近，位置不阻挡移动或战斗。
实现初始位置采用世界坐标(120,230)，无需NPC寻路、碰撞或复杂动画。
玩家存活且与铁匠距离不超过64时显示“F 铁匠”。
按F边沿触发打开；已打开时F关闭。距离不足时不打开，并提供明确中文反馈。

铁匠面板：

- 列出全部4张配方，显示产物模板、固定品质、未学/已学状态。
- 显示各配方拥有张数、每项材料拥有量/需求量。
- 未学且持有配方时“学习”可点；已学显示“已学会”，不提供重复消耗按钮。
- 已学且材料足够时“打造”可点；不足/未学时置灰并明确显示原因。
- 每次左键按下只学习/打造一次，不使用按住连续攻击的输入重复触发。
- 成功打造后显示实际装备名称、品质和随机词缀；资源余量立即更新。
- 本轮无配方拖拽、批量操作、自动学习、自动穿戴、出售或分解。

铁匠面板打开时，整个战斗模拟和动画暂停，FPS仍正常显示。
铁匠面板与I背包互斥；按I打开背包时关闭铁匠，按F成功打开铁匠时关闭背包。
Esc有面板时只关闭当前面板，没有面板时才退出游戏。
面板打开期间R不触发重开；关闭面板的那一帧也不处理战斗移动/攻击/拾取/R，
避免点击或按键穿透。暂停窗口中不处理攻击。
同帧输入优先级为关闭/切换面板，再处理面板操作，最后才是无面板的战斗输入。
未打开面板时保持原有连续攻击行为，下一帧持续按住可继续攻击。
失焦继续冻结模拟和动画，恢复窗口不重放旧点击。
死亡人物不能打开/切换背包或铁匠面板，也不能学习或打造。

新增文本继续集中在GameText并纳入中文字体字符集及布局验证，不硬编码在绘制循环中。
铁匠用现有几何绘制风格，不引入外部美术或新依赖。

## 学习与打造事务

学习和打造均通过Gameplay服务执行，服务检查人物存活和铁匠交互距离，
而不只依靠按钮置灰；UI不能绕过门禁。

学习：

1. 检查配方定义、人物门禁、是否已学、拥有数量。
2. 已学或未拥有等正常拒绝返回明确原因，不扣数量。
3. 成功时一次提交配方数量减1及已学集合增加。
4. 学会后可无限次按费用打造；重复掉落的配方保留在资源袋，不自动转换/删除。

打造：

1. 检查配方定义、人物门禁、已学状态及全部材料数量。
2. 按模板和固定品质生成完整候选装备，复用词缀规则与实例校验。
3. 在任何集合写入前验证装备可入包、所有材料扣除候选值合法。
4. 一次提交全部材料扣费与装备入包，单线程流程中不留部分状态。
5. 失败不扣材料、不学习配方、不入包半成品、不影响原装备及人物生命。

不以“先扣材料，异常时再加回”的回滚拼凑原子性。
可以对现有装备操作增加窄内部的校验/提交协作能力，
但不能开放任意列表写入、让UI直接操作或重复一套装备校验。
实例ID碰撞或配置错误显式失败；不吞异常当作成功。
普通拒绝包括死亡、距离不足、未拥有配方、已学、未学、材料不足，
由Game显示中文结果，不宽泛catch。
打造未穿装备不会读取新装备为人物总属性，更不会隐式换装。

## 随机与奖励生命周期

沿用现有共享Random，不在本轮拆分暴击、资源和打造随机流。
因生产掉落内容已改变，不要求旧装备掉落随机序列不变。
同一击杀内按材料数量 → 是否掉配方 → 成功时选择配方的顺序抽样；
失败的配方概率不再抽配方选择。
多目标击杀仍逐怪同步处理，保持目标顺序，不能延后到动画结束或下一帧。

固定品质打造直接生成词缀，不额外抽品质；正常门禁/材料拒绝不消耗随机数。
生成阶段异常必须传播，不承诺回滚已经消费的随机数，但归属与资源不部分提交。
已有轮次＋怪物实例去重保留，重复记录不产生新地面资源、不消耗随机。
R/复活进入新轮次后同配置怪物可以再次掉落；去重集合只持有当轮数据。

## 验收

自动测试覆盖：

- 内容加载：重复ID、未知材料/配方/模板、非法品质、重复费用项、非正费用、
  非法数量/概率及词缀池不足明确失败；文件路径和引用信息可定位。
- 生产三类怪物各掉指定1～2材料、独立20%配方及四张等权，绝不直接掉装备。
  测概率边界与选择票据，不依靠不稳定的统计抽样。
- 地面叠放显示、按E单堆拾取、身份去重、失败不删地面、不溢出。
- 资源堆叠；首次学习扣1，重复学习不消耗，学会后可反复打造。
- 四张配方精确费用、固定品质/模板、合法词缀与唯一新实例，
  连续打造逐次扣费，材料不足及生成异常无部分写入。
- 死亡、距离门禁，死亡/R保留资源/知识/装备但清地面；
  重开新轮次奖励正常、重复击杀不额外消费随机。
- 输入边沿、面板互斥、Esc关闭优先、R暂停门禁、关闭帧无战斗穿透，
  失焦冻结和FPS保持，原战斗/动画行为回归。
- 真实窗口smoke：获得材料与配方、E拾取、F开铁匠、学习、
  打造、查看实际属性、I穿戴、死亡/重开保留状态及中文布局；
  必要时更新旧“怪物直接掉装备”的fixture，不删掉装备实例和穿戴断言。

Release构建零警告、相关及完整测试、现有格式检查和diff检查通过。
普通/发布版真实窗口smoke都要尝试。
当前环境曾在初始化报NoSuitableGraphicsDeviceException（无图形适配器）；
若仍受阻，记录具体错误并区分逻辑验收与窗口验收，不静默跳过或伪造通过。
不宣称实现了退出重进保留或人工视觉验收。
