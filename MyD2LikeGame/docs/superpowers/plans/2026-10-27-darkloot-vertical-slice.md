# DarkLoot Vertical Slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a runnable Windows top-down ARPG slice in which the player defeats one monster, collects its equipment drop, equips it, and sees the resulting attack increase.

**Architecture:** Keep item/content definitions and gameplay rules independent of MonoGame, then compose them in a MonoGame Windows host. Use JSON for the sample content and a headless test project for data, combat, inventory, and loot behavior; postpone the editor and content builder.

**Tech Stack:** C#, .NET SDK 9.0.320, MonoGame WindowsDX, System.Text.Json, xUnit.

## Global Constraints

- The available SDK is .NET 9.0.320.
- The target is Windows desktop.
- The first arena, characters, equipment, and drop are rendered from simple generated shapes using MonoGame's 2D drawing path. No external art or visual editor is required.
- `Gameplay` depends on `Data` but not MonoGame.
- Malformed JSON, missing referenced IDs, and invalid gameplay values must produce actionable errors rather than silently substituting success-shaped defaults.
- Keep the initial slice to one player, one monster type, directional melee, one equipment definition, and one loot table.
