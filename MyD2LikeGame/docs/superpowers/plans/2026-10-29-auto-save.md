# Automatic Persistence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Retain exact equipment, resources and learned recipes across game runs.

**Architecture:** A headless Gameplay persistence boundary validates and restores
complete progression snapshots. A JSON store atomically commits files; a session
coordinator detects changes and disables saving after any persistence failure.
The host owns load/update/exit integration and visible failure reporting.

**Tech Stack:** Existing .NET 9, System.Text.Json, xUnit, MonoGame.

## Global Constraints

- Production save: `%LOCALAPPDATA%\DarkLoot\save.json`.
- No new packages, migration, manual controls, multiple slots or combat snapshots.
- Invalid/missing references and unsupported versions fail explicitly; only an
  absent file starts fresh.
- Preserve exact instance IDs, rarity, rolls, inventory order and equipped IDs.
- Restore a fresh encounter at spawn with full equipment-adjusted health.
- Atomic same-directory writes; never overwrite a failed-load/save file on exit.
- Smoke tests must never touch a player's production save.

## Task 2: Atomic files and automatic session

**Files:** create `Persistence\JsonSaveStore.cs`, `Persistence\SaveSession.cs`;
test `Gameplay\JsonSaveStoreTests.cs`, `Gameplay\SaveSessionTests.cs`.

**Interfaces:** `JsonSaveStore(string path)` exposes `Load()` returning a nullable
`ProgressSnapshot` and `Save(ProgressSnapshot)`; `SaveSession` exposes
`Load(ArenaSimulation)`, `SaveIfChanged(ArenaSimulation)`, `SaveOnExit(ArenaSimulation)`.
The session loads once, tracks the last successfully serialized snapshot and
disables all writes after a load or save failure.

- [ ] Write tests for absent/malformed/versioned files, repeated replacement,
  failure retaining old bytes, and exact load after a separate session.
  ```csharp
  store.Save(first);
  store.Save(second);
  Assert.Equal(JsonSerializer.Serialize(second),
      JsonSerializer.Serialize(store.Load()));
  ```
- [ ] Run the three persistence test classes; require initial red failures.
- [ ] Implement strict JSON reading, bounded errors with paths, unique temporary
  files, flush-to-disk and File.Replace/File.Move. Catch only expected persistence
  errors, preserve causal exceptions, and clean only the owned temporary file.
- [ ] Implement change comparison and failed-operation guards. Verify no file
  writes on unchanged frames, all four mutations save, and exit forces a save.
- [ ] Run focused tests and commit storage/coordinator.
