# Gothic Dual-panel UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the approved original gothic HUD, dual panels and unlimited 8x4 inventory.

**Architecture:** Shared viewport geometry owns rendering/hit-test bounds. A
dual-panel controller consumes interface commands before world intent; existing
Gameplay services remain authoritative. Original generated stone/metal/globe
textures and icons provide a shared render vocabulary.

**Tech Stack:** Existing .NET 9, MonoGame 3.8.6, xUnit; no new dependencies.

- Existing isolated branch: `feature/darkloot-vertical-slice`; baseline 369 tests.

- One cell per equipment instance, 8x4 pages, unlimited capacity; no save changes.

## Task 1: Shared geometry and independent-panel routing

**Files:** create `src\DarkLoot.Game\UiLayout.cs`; modify `PanelController.cs`;
update `tests\DarkLoot.Tests\Game\PanelControllerTests.cs` and test source links.

**Interfaces:** `UiLayout(int width, int height = 720)` exposes `Console`,
`Inventory`, `Blacksmith`, inventory tabs/cells/page controls, recipe rows and
detail-action controls, close controls and console command bounds. Cell size and
all pointer targeting derive from this one layout.
`PanelController` exposes `InventoryOpen`, `BlacksmithOpen`, most-recent
`ActivePanel`; `PanelFrame` carries both visibility flags, world/action/exit/reset
decisions and world-input suppression. `Route` accepts viewport width/height.

## Task 2: Original reusable UI art

**Files:** create `src\DarkLoot.Game\GothicUiRenderer.cs` and focused art tests.

**Interfaces:** `GothicUiRenderer(GraphicsDevice, ShapeRenderer)` is disposable.
Expose `DrawPanel`, `DrawConsole`, `DrawWell`, `DrawButton`, `DrawIcon` and
`DrawHealthGlobe`, all receiving SpriteBatch and Rectangle bounds; button/well
states are booleans. `UiIcon` values: Weapon, Armor, Bone, Hide, Slime, Recipe,
Material. Public static palette: Text, Muted, Gold, Blue, Red, Green.
Textures are generated once, cached, and disposed; supplied ShapeRenderer is
borrowed, never disposed by this class.

- [x] Write focused failing tests for the generated globe transparency/fill
  geometry, ensuring no fill outside its circular mask and correct empty/full
  clipping. Use actual texture pixel generation, not assertions about constants.
- [x] Run focused tests, implement original stone/noise/bevel/glass/liquid/ring
